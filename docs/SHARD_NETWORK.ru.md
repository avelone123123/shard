# Глобальная децентрализованная сеть SHARD Network — Архитектура и Руководство
## 1. Введение
SHARD Network — это децентрализованная открытая экосистема, позволяющая пользователям по всему миру запускать локальные модели ИИ, предоставлять к ним защищённый доступ и объединяться в распределённые вычислительные сети без платных облачных посредников и подписок.
## 2. Архитектурные принципы
- Суверенная криптографическая идентификация: каждый узел генерирует постоянный идентификатор Ed25519 (`shn_<40hex>`).
- Изоляция данных на Discovery: серверы обнаружения хранят исключительно подписанные метаданные с TTL-сроком жизни; трафик инференса через них не проходит.
- Слепая ретрансляция (Blind Relay): реле пересылает только зашифрованные пакеты `ChaCha20-Poly1305` с 16-байтными открытыми AAD-заголовками; реле не имеет ключей расшифровки промптов и ответов.
- Изоляция прав владельца: запросы через туннели блокируются от вызова административных маршрутов `/api/*`.
- Детерминированный выбор маршрута: `same_machine -> direct_lan -> direct_p2p (STUN/UDP) -> blind relay`. Статус подключения присваивается только после успешного проверочного пинга `/v1/ping`.
- Автономность при отсутствии сети: режим `offline_only=True` гарантирует полноценную работу локального сервера и LAN-кластера без внешних сетевых запросов.
## 3. Криптография и протокол связи
- Идентификатор узла: префикс `shn_` с 40 шестнадцатеричными символами (хеш SHA-256 от открытого ключа Ed25519).
- Рукопожатие: 3-фазный обмен эфемерными ключами X25519 Diffie-Hellman с валидацией подписи Ed25519.
- Формат кадра: 16 байт AAD (`ver`, `msg_type`, `flags`, `stream_id`, `seq`), зашифрованное тело и 16 байт Poly1305 тега.
- Защита от повторов: строгий контроль монотонно возрастающих номеров пакетов (`seq`).
## 4. Развёртывание собственных серверов
### Discovery-сервер
```bash
shard network discovery-serve --host 0.0.0.0 --port 8090 --rate-limit 120
```
### Blind Relay-сервер
```bash
shard network relay-serve --host 0.0.0.0 --port 8091 --max-tunnels-per-host 32 --max-kbps 10240
```
### Docker Compose
```bash
docker compose -f docker-compose.network.yml up -d
```
### Сервисы Systemd
В каталоге `deploy/systemd/` подготовлены шаблоны юнитов:
- `deploy/systemd/shard-discovery.service`: изолированный сервис обнаружения с запуском от отдельного пользователя.
- `deploy/systemd/shard-relay.service`: высокоскоростной слепой релей-сервер.
- `deploy/systemd/shard-user.service`: локальный инференс-сервис SHARD с автоперезапуском.
## 5. Матрица безопасности и доступа
- `/v1/ping`: публичный маршрут для измерения сетевой задержки.
- `/v1/models`, `/v1/chat/completions`: разрешены авторизованным туннельным узлам и владельцам локальных токенов.
- `/api/*`: строго изолированы для локального владельца (`127.0.0.1` без туннельных заголовков или с токеном владельца). Удалённые узлы получают HTTP 403.
- Защита от подделки заголовков: заголовок `X-Shard-Bridge-Token` валидируется по динамическому секрету в памяти. Наличие заголовков туннеля блокирует эскалацию привилегий до уровня владельца.
## 6. Команды интерфейса CLI
- `shard network status`: текущий статус узла, режим работы, число пиров и адреса серверов.
- `shard network identity`: открытый криптографический ключ Ed25519 и цифровой отпечаток.
- `shard network config`: просмотр и редактирование параметров сети и серверов.
- `shard network servers`: поиск доступных серверов в каталоге Discovery.
- `shard network publish`: публикация локального сервера в каталоге Discovery.
- `shard network unpublish`: снятие сервера с публикации.
- `shard network connect <target>`: установление туннеля к удалённому серверу.
- `shard network disconnect`: завершение текущего подключения.
- `shard network invite create|list|revoke`: управление пригласительными ссылками (`shinv1_*`).
- `shard network peers`: просмотр активных, ожидающих и заблокированных пиров.
- `shard network approve|reject|kick|block|unblock`: управление доступом удалённых узлов.
- `shard network quota <peer> --rpm <n> --kbps <n>`: настройка лимитов запросов и скорости для конкретного узла.
- `shard network wg`: проверка состояния драйвера и подсистемы WireGuard.
- `shard network doctor`: диагностика сетевого экрана, трансляции адресов STUN NAT и портов.
